Результат для получателя

Выберите, что получит читатель или библиотекарь на каждом пути.

Библиотекарь видит в истории правильную карточку, а в самой заявке приходит только исходная фраза читателя. Обработчик уже справился. Осталось объяснить приложению, какой именно результат отдать получателю. В этом уроке вы настроите конечный узел Output для каждого пути.

Перед запуском. После шаблона доступны исходное сообщение «Вернул журнал» и готовая строка «Карточка: Вернул журнал». Как понять, какая из двух переменных нужна тому, кто печатает карточки? Какую выберете для печати?
Сверить прогноз

Отталкивайтесь от того, что получатель должен увидеть. Для печати нужна готовая строка с пометкой. Даже если в исходном сообщении уже есть название журнала, это ещё не готовая карточка. Теперь подберите нужный источник для каждой из двух ветвей.

Верните обработанные данные

  1. На ветке Template откройте «Output · карточка». Дайте результату имя ticket. Выберите источник готовой строки, которую подготовил шаблон.
  2. На ветке LLM откройте «Output · ответ». Дайте ему отдельное имя answer и выберите источник ответа, подготовленного моделью.
  3. Запустите возврат, затем вопрос. В первый раз в результате нужна пара с именем ticket и пометкой «Карточка: ». Во второй раз нужна пара answer и подтверждение «Принято: ». Проверьте настройки на новых обращениях.
Нужна подсказка

Источник значения и его имя на выходе задаются отдельно. Источник ищите у предыдущего обработчика: у Template его переменная называется output, а у LLM — text. Названия ticket и answer использует потребитель готового приложения.

Чем внутренний результат отличается от внешнего

Допустим, читатель написал «Куда принести карту?». Это один текст. Модель подготовила подтверждение «Принято: Куда принести карту?». Это уже второй текст. В конце схемы доступны оба. Возможность выбрать один из них полезна: автор приложения определяет, какие данные действительно потребуются снаружи.

Каждый результат похож на подписанный конверт. Имя вроде answer говорит следующей программе, где искать ответ, а значение внутри содержит сам ответ. Если конверт правильно подписан, но в него положили исходный вопрос, читатель всё равно не получит нужного сообщения. Поэтому мы отдельно проверяем имя и содержимое.

В этом проекте разработчик формы ожидает два разных исхода. По ticket он отправит карточку библиотекарю, по answer — покажет подтверждение читателю. Менять эти имена внутри узлов на произвольные синонимы нельзя без изменения договорённости с получателем. Подпись поля ввода для человека при этом может быть любой понятной фразой.

Если результат удивил

В Result есть ключ ticket с фразой читателя, но без пометки «Карточка: ». Что быстрее выяснит причину: правка текста шаблона наугад или сравнение соседних шагов истории?

Разобрать причину

Откройте Template в Tracing. Если его output уже начинается с нужной пометки, шаблон исправен. Затем откройте конечный Output и посмотрите выбранный источник. Укажите результат шаблона и испытайте тот же ввод. В другой ветке выполните такую же сверку с результатом модели.

Попробуйте в другой ситуации

Мастерская отдаёт бухгалтеру сумму ремонта. Внутри схемы есть стоимость деталей и полная сумма с работой. Слово total уже согласовано с бухгалтером. Какой признак покажет, что в последнем узле выбран верный источник?

Сверить ход решения

Проверьте заказ, где работа стоит ощутимо больше нуля. На выходе должно появиться имя total с полной суммой. Заказ с бесплатной работой не различит два источника: число совпадёт при обеих настройках. Сильный пробный пример делает ошибочную настройку заметной.

Как повторить в настоящей Dify

В Dify добавьте узел Output на нужной ветке. В его списке выходов укажите имя результата и выберите переменную из доступных узлов. Проверьте, какую переменную предлагает именно ваш обработчик. За один запуск Workflow проходит только по выбранному пути; наличие двух конечных узлов на холсте само по себе не означает два ответа на одну заявку.

Открыть руководство Dify по теме урока

Как работать с тренажёром и проверкой

Каждый урок начинается со своей заготовки. Можно открыть его отдельно, даже если вы проходили предыдущий на другом устройстве. Названия на английском помогают найти те же действия в редакторе Dify. Выберите узел в схеме, затем измените его настройки в соседней панели. На узком экране панель находится под схемой. Между кнопками и полями можно перемещаться клавишей Tab.

Перед пробой запишите, что должно получиться. При наличии полей заполните форму и нажмите Start Run. Без полей первый урок запускается сразу. Сначала прочтите результат целиком. Если ожидали другое, откройте Tracing и выберите шаг, на котором хотите увидеть вход и выход. Вернитесь в Orchestrate, чтобы отредактировать схему. После изменения сделайте новый запуск.

Кнопка «Проверить задание» сверяет решение с условиями урока. Если увидите пример, на котором схема ошиблась, повторите его в панели запуска. Отметка о прохождении сохраняется в этом браузере при разрешённом локальном хранении. Задание можно выполнять повторно.
