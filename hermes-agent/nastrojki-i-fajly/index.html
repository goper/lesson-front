Настройки и файлы

Что лежит в папке ~/.hermes и как менять настройки, не открывая файлы.

Основная идея урока

Всё, что Hermes знает и помнит, лежит в одной папке ~/.hermes. Настройки разделены на два файла: config.yaml для обычных настроек и .env для секретов. Команда hermes config set сама кладёт значение в нужный файл.

Ключ на скриншоте

У вас что-то не работает, и вы просите коллегу помочь: отправляете скриншот файла настроек. Через день на счету у провайдера минус 40 долларов. В файле лежал API-ключ, а скриншот ушёл в общий чат.

Чтобы такого не случалось, Hermes хранит настройки в двух разных местах. Одно можно показывать, другое нельзя. Разберёмся, что где.

Папка ~/.hermes

Значок ~ означает вашу домашнюю папку. Точка в начале имени делает папку скрытой: в обычном списке файлов её не видно. Внутри лежит всё рабочее место стажёра.

Нажимайте на строки. Дерево упрощено: в настоящей папке есть ещё служебные файлы.
!
Теперь понятно, почему папку не удаляют

В уроке 2 было правило: не чинить удалением ~/.hermes. Теперь видно почему. В одной папке лежат и код программы, и всё нажитое: настройки, ключи, память, навыки, разговоры. Код восстановить легко, остальное нет.

Два файла настроек

!
Образ: инструкция на стене и сейф

config.yaml — инструкция на стене у рабочего места стажёра: «работаем с такой-то моделью, команды выполняем там-то». Её может прочитать любой, кто зашёл в комнату. .env — сейф с ключами: от счёта у провайдера, от бота в Telegram. Сейф не фотографируют.

Команды для настроек

Файлы можно править в редакторе, но проще и безопаснее командой: она проверит имя настройки и не даст ошибиться файлом.

ЗадачаКомандаКуда попадёт
Сменить модель по умолчаниюhermes config set model anthropic/claude-sonnet-4.6config.yaml
Сохранить ключ провайдераhermes config set OPENROUTER_API_KEY sk-or-….env
Переселить агента в контейнерhermes config set terminal.backend dockerconfig.yaml
  • hermes config — показать текущие настройки.
  • hermes config get ИМЯ — показать одно значение.
  • hermes config set ИМЯ ЗНАЧЕНИЕ — записать значение. Используем постоянно.
  • hermes config unset ИМЯ — убрать свою настройку и вернуться к значению по умолчанию.
  • hermes config edit — открыть config.yaml в редакторе.
  • hermes config check и hermes config migrate — проверить и дополнить настройки после обновления (урок 2).
Прогноз. Вы набрали hermes config set OPENROUTER_API_KEY sk-or-abc123. В какой файл попадёт значение?

В .env. Hermes смотрит на имя: ЗАГЛАВНЫЕ_БУКВЫ_С_ПОДЧЁРКИВАНИЕМ означают переменную окружения, а они живут в .env. Имя строчными с точкой, как terminal.backend, попало бы в config.yaml.

Если вы ответили «в config.yaml, команда же называется config», это логичная догадка. Команда одна, а файлов два. Раскладывает она по имени настройки.

Кто главнее: порядок настроек

Одну и ту же вещь иногда можно задать в нескольких местах. Например, модель записана в config.yaml, а вы запустили Hermes с флагом --model. Кого он послушает? Hermes идёт по списку сверху вниз и берёт первое найденное.

  1. сначала флаги запуска То, что вы написали прямо в команде, главнее всего. hermes chat --model anthropic/claude-opus-4.6 возьмёт эту модель, что бы ни было в файлах. Действует только на этот запуск.
  2. потом config.yaml Флага нет — Hermes читает инструкцию на стене. Здесь лежит ваша постоянная настройка.
  3. потом .env В config.yaml настройки нет — проверяется .env. Для секретов это основное место, для остального запасное.
  4. в конце встроенное значение Нигде ничего не задано — берётся то, что заложили разработчики. Например, terminal.backend по умолчанию local.
В config.yamlКак запустилиКакая модель работает
model: anthropic/claude-sonnet-4.6hermesclaude-sonnet-4.6: из файла
model: anthropic/claude-sonnet-4.6hermes chat --model anthropic/claude-opus-4.6claude-opus-4.6: флаг главнее файла. В следующий раз без флага снова будет sonnet
строки model нетhermesHermes попросит выбрать модель (урок 2)

Ловушка: ключ в инструкции на стене

Если открыть config.yaml в редакторе и вписать туда ключ, он может даже сработать. Но теперь сейф пуст, а ключ висит на стене. Первый же скриншот, первая отправка файла коллеге, первая синхронизация настроек между компьютерами — и ключ ушёл. Пользуйтесь hermes config set: она положит ключ в .env сама.

Проверьте себя
В config.yaml записано backend: docker. Вы выполнили hermes config unset terminal.backend. Где теперь будут выполняться команды?
  • В контейнере: docker остался
  • На вашем компьютере: local
  • Нигде: терминал отключится
  • Hermes спросит при запуске

ТренажёрВместе. Выполните пять настроек. После каждой команды смотрите, какой файл справа подсветился.

В настоящем config.yaml намного больше строк и разделов, а сообщения команд сформулированы иначе. Принцип тот же: одна команда, два файла, выбор по имени настройки.

Что вы теперь умеете

  • Находить нужное в папке ~/.hermes.
  • Менять настройки командами hermes config get, set, unset.
  • Отличать инструкцию на стене (config.yaml) от сейфа (.env).

Подумайте о своей рутине из урока 1. Какие секреты для неё понадобятся: ключ провайдера, токен бота, пароль к чему-то? Все они окажутся в одном файле, который нельзя показывать.

Почему в YAML важны отступы и нельзя повторять имена

config.yaml написан в формате YAML. В нём вложенность задаётся отступами из пробелов:

terminal:
  backend: docker
  timeout: 180

Здесь backend и timeout находятся внутри terminal, потому что сдвинуты на два пробела. Уберёте отступ — получится совсем другая настройка. И вторая ловушка: если раздел с одним именем написан в файле дважды, второй молча заменит первый. Ошибки не будет, просто половина настроек перестанет работать. Это ещё одна причина пользоваться hermes config set.

Профили: несколько рабочих мест

Если нужен отдельный агент для работы и отдельный для личных дел, есть профили. hermes -p work запускает Hermes с отдельным набором настроек, памяти и навыков в папке ~/.hermes/profiles/work/. Для первых недель достаточно одного профиля.

Как защитить сейф

Памятка по безопасности из документации советует закрыть файл с секретами от других пользователей компьютера:

chmod 600 ~/.hermes/.env

После этого читать и менять файл можете только вы. И напоминание из урока 4: у агента ваши права, значит он тоже может прочитать этот файл. Ещё один довод не включать YOLO.

Итог урока

Главная мысль: Вся жизнь Hermes лежит в ~/.hermes. Обычные настройки хранятся в config.yaml, секреты в .env, а команда hermes config set сама выбирает файл по имени настройки.

  • config.yaml — инструкция на стене, её можно показывать. .env — сейф, его не показывают.
  • Имя ЗАГЛАВНЫМИ_С_ПОДЧЁРКИВАНИЕМ идёт в .env, имя строчными.с.точкой — в config.yaml.
  • hermes config get / set / unset — посмотреть, записать, убрать.
  • Порядок: флаг запуска, потом config.yaml, потом .env, потом встроенное значение.
  • Не вписывайте ключи в config.yaml руками.
