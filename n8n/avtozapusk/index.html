Автозапуск: расписание, вебхуки, активация

Как workflow начинает работать сам, без вашей кнопки.

Основная идея урока

Для автозапуска задайте триггер (например, расписание) и опубликуйте workflow кнопкой Publish. Дальше можно закрыть браузер. В тренажёре показан предыдущий интерфейс: ту же задачу вы выполните кнопкой Save и переключателем Active.

Запуск по расписанию

Schedule Trigger — самый простой автоматический триггер. Вы задаёте интервал: каждые N секунд, минут, часов, дней, недель или месяцев, и время срабатывания. В нужный момент n8n сам создаёт один элемент с текущей датой и запускает цепочку.

ТренажёрНастройте Schedule Trigger так, чтобы workflow запускался каждый день в 8:30. Нажмите Execute step и посмотрите, какие данные выдаёт триггер.
!
Часовой пояс

Расписание считается в часовом поясе workflow. Он задаётся в настройках workflow (меню «⋯» → Settings → Timezone). По умолчанию берётся часовой пояс сервера n8n, и 9:00 может оказаться не вашим 9:00.

Запуск по внешнему событию: Webhook

Webhook («вебхук») — это адрес, который n8n выдаёт вашему workflow. Любой сервис или сайт может отправить на этот адрес запрос с данными, и workflow запустится. Так подключают формы на сайте, платёжные системы, CRM: они умеют «дёргать адрес», когда у них что-то случилось.

Прогноз. Вы дали сайту адрес вебхука, в котором есть слово «webhook-test», и ушли пить чай. Сайт отправил заявку. Что произойдёт?

Ничего. Адрес с «webhook-test» — это Test URL: он ловит один запрос и только пока нажата кнопка «Listen for test event». Для постоянной работы сайту дают другой адрес, Production URL, и публикуют workflow. Если вы ответили «workflow запустится», вы только что нашли главную причину жалобы «вебхук не работает».

У ноды Webhook два адреса. Test URL — для проверки руками: в окне ноды нажимаете «Listen for test event», n8n ловит один запрос и кнопка выключается сама. Production URL работает постоянно, но только когда workflow опубликован и n8n доступен. Именно его дают сайту.

ТренажёрСайт будет присылать заявки методом POST. Выберите HTTP Method, нажмите «Listen for test event», затем кнопку имитации отправки заявки внизу. Посмотрите, где в OUTPUT лежат данные формы.
До публикацииПосле публикации
Test URLЛовит один запрос, пока нажата «Listen for test event»То же самое
Production URLНе работаетРаботает круглосуточно. Его даём сайту
ТренажёрСломайте. В тренажёре workflow сейчас Inactive. Переключите адрес на Production URL и нажмите кнопку «сайт отправил заявку» внизу. Посмотрите, что придёт в OUTPUT.
!
Данные вебхука лежат в body

Нода Webhook выдаёт элемент с частями headers (служебное), query (параметры адреса) и body (данные формы или сервиса). Поэтому имя клиента — это {{ $json.body.name }}, а не {{ $json.name }}. Частая ошибка новичков.

Проверьте себя
Форма прислала поле amount. В If вы написали {{ $json.amount }}, и слева в условии показывается [undefined]. Что исправить?
  • Написать {{ $json.body.amount }}
  • Опубликовать workflow
  • Сменить Test URL на Production URL
  • Переключить HTTP Method на GET

Публикация и автоматические запуски

В актуальном редакторе проверьте черновик, нажмите Publish и подтвердите публикацию. При следующем событии n8n запустит опубликованную версию. Если есть только ручной триггер, ждать фоновых запусков бессмысленно: добавьте, например, Schedule Trigger.

ТренажёрСоберите workflow: Schedule Trigger → Telegram. Сохраните его и переключите Inactive → Active. Попробуйте также, что будет, если сначала выбрать ручной триггер.
  • Опубликованный workflow с автоматическим триггером запускается по событию. Его по-прежнему можно запускать и вручную кнопкой для проверки.
  • Изменили ноду в опубликованной цепочке — проверьте и опубликуйте черновик заново. До этого рабочие события обрабатывает предыдущая версия.
  • Каждый автоматический запуск виден во вкладке Executions.

Что вы теперь умеете

  • Настраивать Schedule Trigger: интервал, час, минута, часовой пояс.
  • Отличать Test URL от Production URL и знать, когда работает каждый.
  • Настраивать автозапуск и объяснять, почему с одним ручным триггером это невозможно.

Подумайте о своём: как будет запускаться ваша автоматизация из урока 1? По времени, по запросу от сайта или по событию в сервисе? Назовите триггер, а если это расписание, то и время. В уроке 10 это станет первой нодой вашей схемы.

Cron: расписание для сложных случаев

В Schedule Trigger есть вариант Custom (Cron): запись из пяти частей «минута час день месяц день_недели». Звёздочка означает «любой». Примеры:

CronКогда
0 9 * * 1-5В 9:00 по будням
*/15 * * * *Каждые 15 минут
0 18 1 * *Первого числа каждого месяца в 18:00
30 7 * * 1По понедельникам в 7:30
Ответ вебхуку: настройка Respond

Тот, кто отправил запрос на вебхук, ждёт ответ. По умолчанию (Immediately) n8n сразу отвечает «принято» и обрабатывает данные дальше. Вариант When Last Node Finishes отдаёт результат последней ноды. Вариант Using Respond to Webhook Node позволяет собрать ответ самому в отдельной ноде: так делают, когда сайт должен показать пользователю, например, номер заявки.

Другие триггеры приложений

Многие готовые ноды имеют и версию-триггер: Gmail Trigger, Telegram Trigger, Google Sheets Trigger, Notion Trigger. Внутри они работают по-разному: одни получают вебхук от сервиса, другие сами опрашивают сервис раз в минуту (это называется polling). Для вас разницы почти нет: выбрали событие, настроили credential, опубликовали workflow.

Итог урока

Главная мысль: Чтобы workflow работал сам: автоматический триггер (Schedule, Webhook, событие приложения) и публикация. Test URL вебхука для проверки, Production URL для реальной работы.

  • Schedule Trigger: интервал + время, часовой пояс в настройках workflow.
  • Webhook: данные лежат в body, значит {{ $json.body.поле }}.
  • Production URL принимает события опубликованной цепочки.
  • С одним ручным триггером активировать нечего.
Проверка знаний
1. Workflow с Schedule Trigger настроен на 9:00, но ничего не запускается. Самая вероятная причина?
  • Версия с этим расписанием не опубликована
  • Вкладка браузера была закрыта
  • Не хватает ручного триггера
  • Расписание сработает только завтра
2. Какой адрес вебхука дать сайту для постоянной работы?
  • Test URL
  • Production URL
  • Любой из двух
  • Адрес редактора n8n
3. Сайт прислал на вебхук поле name. Как к нему обратиться в следующей ноде?
  • {{ $json.name }}
  • {{ $json.body.name }}
  • {{ $json.query.name }}
  • {{ $json.headers.name }}
4. В тренажёре только ручной триггер. Что произойдёт при попытке включить Active?
  • Workflow начнёт запускаться каждую минуту
  • n8n сообщит, что активировать нечего
  • Ручной триггер заменится на Schedule
  • Переключатель включится, но ничего не изменится
5. Что означает cron-запись 0 9 * * 1-5?
  • Каждые 9 минут по будням
  • В 9:00 каждый день
  • В 9:00 по будням
  • В 0:09 с первого по пятое число
6. Повторение. Из формы сумма пришла как "1200", в кавычках. В If стоит оператор Number: is greater than, и нода падает с Wrong type. Что сделать?
  • Включить в If Convert types where required
  • Поменять оператор на String: is equal to 1200
  • Заменить Webhook на Schedule Trigger
  • Добавить Aggregate перед If
7. Повторение. Schedule Trigger сработал в 8:30. Сколько элементов он отдаст следующей ноде?
  • Один, с текущей датой и временем
  • Ноль: расписание данных не даёт
  • По одному на каждую минуту с прошлого запуска
  • Столько, сколько строк в таблице
