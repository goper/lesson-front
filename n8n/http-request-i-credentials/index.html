Внешние сервисы: HTTP Request и credentials

Как n8n разговаривает с другими программами и где хранить ключи доступа.

Основная идея урока

Чтобы n8n работал с внешним сервисом, нужны две вещи: нода, которая умеет с ним говорить (готовая интеграция или универсальный HTTP Request), и credentials — ключ доступа, который вводится один раз и хранится отдельно от workflow.

Как программы общаются: API простыми словами

У большинства сервисов есть API (программный интерфейс) — набор адресов, по которым можно попросить сервис что-то сделать или отдать данные. Представьте ресторан. Вы сидите за столом: это n8n. Меню — документация сервиса: список того, что можно попросить. Официант — API: он принимает заказ, уносит на кухню и приносит блюдо. На кухню вы не ходите.

  • Запрос — заказ. В нём адрес (URL), метод (GET «дай», POST «прими») и иногда параметры: «погода, город Минск».
  • Ответ — блюдо. В нём код статуса и данные, почти всегда в JSON. Код — это реплика официанта: 200 «пожалуйста, ваш заказ», 404 «такого блюда нет в меню» (ошибка в адресе), 401 «а вы кто? у нас по клубным картам» (нужен ключ доступа), 429 «кухня перегружена, подождите» (слишком частые запросы).
  • В n8n ответ превращается в обычные элементы на выходе ноды. Дальше с ними работают как с любыми данными.

Готовая нода или HTTP Request

Для популярных сервисов (Gmail, Telegram, Google Sheets, Notion, Slack…) в n8n есть готовые ноды. Там не нужно знать адреса: выбираете действие «отправить сообщение» и заполняете поля. Если готовой ноды нет или она не умеет нужное действие, берут HTTP Request: универсальную ноду, в которую вписывают адрес из документации сервиса.

!
Правило выбора

Сначала ищите готовую ноду по названию сервиса. Не нашли или не хватает действия — HTTP Request. Обе работают с одними и теми же credentials.

Уточнения к запросу передают параметрами: это добавка к адресу после знака вопроса, например ?city=Minsk. В ноде HTTP Request для них есть переключатель Send Query Parameters: включили, и появились строки «имя — значение».

ТренажёрЗапросите погоду в два шага. Шаг 1, сломайте: впишите адрес https://api.weather.example/today, метод GET, и нажмите Execute step без параметров: прочитайте, что ответит сервер. Шаг 2: включите Send Query Parameters, добавьте параметр city со значением Minsk и выполните снова.
Проверьте себя
Сервер ответил кодом 404. Что это значит?
  • Всё хорошо, данные получены
  • Нужен ключ доступа, сервер вас не узнал
  • По такому адресу ничего нет: ошибка в URL
  • Слишком много запросов, нужно подождать

Credentials: ключи в одном месте

Большинство сервисов не отвечают кому попало: нужен ключ (токен, логин с паролем или вход через Google). В ресторане это клубная карта: вы один раз получаете её у сервиса и показываете официанту при каждом заказе. В n8n такие карты лежат в отдельном ящике Credentials. Вы создаёте credential один раз, даёте ему имя, например «Telegram бот магазина», а в нодах просто выбираете его из списка. Сам токен в полях ноды не появляется.

  • Один credential можно использовать в десятках workflow. Сменился токен — поменяли в одном месте.
  • Токены хранятся зашифрованными. При экспорте workflow они не уезжают вместе с ним.
  • В готовых нодах поле называется «Credential to connect with». В HTTP Request сначала выбирают Authentication: Predefined Credential Type — готовый тип по имени сервиса (Telegram API, OpenAI). Generic — когда у сервиса свой способ: ключ в заголовке запроса, логин с паролем или вход через кнопку «войти через…».
Прогноз. Вы отправляете запрос к сервису заказов магазина, не указав никакого ключа доступа. Какой код вернёт сервер?

401 Unauthorized: «а вы кто?». Официант не принимает заказ без клубной карты. 404 было бы при неверном адресе, 200 при успехе. Увидели 401: адрес не трогайте, добавляйте Authentication и credential.

ТренажёрЗапросите список заказов https://api.shop.example/orders в два шага. Шаг 1, сломайте: нажмите Execute step без ключа и прочитайте ответ. Шаг 2: выберите Authentication → Predefined Credential Type, создайте credential кнопкой «+ Create new credential» и выполните снова.
!

Типа «Shop API» в n8n нет, это учебный пример. В списке Predefined Credential Type ищите тип по имени настоящего сервиса: Telegram API, OpenAI, Notion API. Если сервиса в списке нет, берите Generic.

Два ключа, которые нужны почти всем

Вход через Google (Gmail, Google Sheets, Drive). Пароль в n8n не вводят. В credential нажимаете «Sign in with Google», Google открывает своё окно, вы выбираете аккаунт и разрешаете доступ. В n8n Cloud это работает сразу. На своём сервере кнопка сначала не сработает: нужно создать ключ OAuth в консоли Google и вписать его в настройки credential. Это отдельная пошаговая инструкция в документации n8n, раздел Google OAuth2.

Telegram: где взять токен бота и Chat ID
  1. Откройте в Telegram бота @BotFather, отправьте /newbot, придумайте имя. В ответ придёт токен вида 123456:ABC-DEF…. Это и есть credential «Telegram API» в n8n.
  2. Напишите своему новому боту любое сообщение (иначе он не сможет писать вам первым).
  3. Узнайте Chat ID — номер чата, куда бот будет слать сообщения. Самый простой способ: открыть бота @userinfobot, он пришлёт ваш Id. Для группы добавьте бота в группу и откройте в браузере https://api.telegram.org/bot<токен>/getUpdates: в ответе будет chat → id, у групп он отрицательный.
  4. В ноде Telegram выберите credential и впишите Chat ID в поле Chat ID. Ошибка «chat not found» почти всегда означает неверный Chat ID или то, что бот не добавлен в чат.
!
Никогда не вписывайте токен прямо в URL или текст

Это как оставить клубную карту на столе: её увидит каждый, кто откроет историю выполнений, экспорт workflow или скриншот. Токен живёт только в credentials. Если он всё же утёк, перевыпустите его в сервисе: старую карту блокируют.

Что вы теперь умеете

  • Выбирать между готовой нодой и HTTP Request.
  • Читать коды ответа как реплики официанта: 200, 401, 404, 429.
  • Создавать credential один раз и выбирать его в нодах по имени.

Подумайте о своём: какие сервисы участвуют в вашей рутине из урока 1? Для каждого ответьте: есть ли готовая нода (поищите в панели нод по названию) и какая «клубная карта» понадобится: токен, вход через Google или логин с паролем.

Методы запросов: GET, POST и остальные
МетодСмыслПример
GETДай данныеПолучить список заказов
POSTПрими новые данныеСоздать заказ, отправить сообщение
PUT / PATCHИзмени существующееОбновить статус заказа
DELETEУдалиУдалить запись

Для POST обычно включают Send Body и передают JSON с данными. Какой метод и какие поля нужны, всегда написано в документации сервиса, обычно в разделе API Reference.

Параметры, заголовки, тело

Query Parameters — добавка к адресу после знака вопроса: ?city=Minsk&days=3. Headers — служебная информация, например формат ответа или ключ доступа. Body — основной груз запроса, нужен для POST и PUT. В ноде HTTP Request для каждого есть свой переключатель Send…, и значения могут быть выражениями: {{ $json.city }}.

Ограничения сервисов: 429 и Batching

Сервисы не любят тысячу запросов в секунду и отвечают кодом 429 Too Many Requests: кухня перегружена, подождите. У ноды HTTP Request в Options есть Batching: сколько элементов отправлять за раз и сколько ждать между партиями. Плюс настройка Retry On Fail во вкладке Settings (урок 9).

Итог урока

Главная мысль: Внешний сервис = нода (готовая или HTTP Request) + credentials. Запрос состоит из метода, адреса и параметров, ответ — из кода и JSON, который становится элементами.

  • Сначала ищите готовую ноду, потом HTTP Request.
  • 200 — успех, 401 — нужен ключ, 404 — нет такого адреса, 429 — слишком часто.
  • Credentials создаются один раз и выбираются в нодах по имени.
  • Токен Telegram даёт BotFather, Chat ID — @userinfobot; Google входит кнопкой Sign in.
Проверка знаний
1. Для сервиса нет готовой ноды в n8n. Что использовать?
  • Ноду HTTP Request с адресом из документации
  • Ноду Webhook с адресом сервиса из документации
  • Ноду Edit Fields с полем URL сервиса
  • Ноду Code: без кода другого пути нет
2. Токен Telegram-бота сменился. Он используется в двенадцати workflow. Сколько мест придётся править?
  • Одно: credential, который выбран во всех нодах
  • Двенадцать: по ноде Telegram в каждом workflow
  • Двенадцать: настройки каждого workflow
  • Ни одного: n8n обновит токен сам
3. Сервер вернул 401 Unauthorized. Что делать?
  • Проверить опечатку в адресе и путь запроса
  • Выбрать Authentication и верный credential
  • Подождать минуту и повторить тот же запрос
  • Сменить метод с GET на POST
4. Какой метод используют, чтобы получить данные, ничего не меняя?
  • GET
  • POST
  • PUT
  • DELETE
5. Куда попадает ответ сервера после выполнения HTTP Request?
  • В OUTPUT ноды, в виде элементов
  • В credentials, рядом с ключом
  • В настройки workflow, вкладка Settings
  • Во вкладку Executions как отдельный запуск
6. Почему нельзя вписывать токен прямо в поле URL?
  • Он попадёт в историю запусков и экспорт
  • n8n откажется сохранять workflow с токеном
  • Сервер не примет токен в адресе
  • URL с токеном станет слишком длинным
7. Повторение. HTTP Request вернул список из трёх заказов. Следующая за ним нода Telegram отправит…
  • Одно сообщение со списком заказов
  • Три сообщения, по одному на заказ
  • Ни одного: список нельзя отправить
  • Ошибку: сначала нужна нода Aggregate
8. Повторение. Сервис погоды ответил карточкой { "temp": 4, "condition": "cloudy" }. Как вставить температуру в текст следующей ноды?
  • {{ $json.temp }}
  • {{ temp }}
  • {{ $json.weather.temp }}
  • $json.temp без скобок
