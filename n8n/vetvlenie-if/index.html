Ветвление: нода If

Как отправить одни элементы в одну сторону, а другие в другую.

Основная идея урока

Нода If проверяет каждый элемент по условию и отправляет его в одну из двух веток: true (условие выполнено) или false (не выполнено). Данные не теряются, они просто расходятся по разным дорогам.

Когда одной дороги мало

Вы собрали workflow из урока 3: заявка с сайта приходит в Webhook и улетает в Telegram менеджеру. Через неделю менеджер просит: «Мне нужны только крупные, больше 1 000. Мелкие просто пишите в таблицу, я их потом сам посмотрю». В цепочке «триггер → Telegram» для этого нет места: все заявки идут по одной дороге. Нужна развилка.

Нода If и есть развилка. Она смотрит на каждый элемент, проверяет условие и отправляет его в один из двух выходов: true (условие выполнено) или false (нет). If не меняет данные и не удаляет элементы: что пришло, то и ушло дальше, просто разными дорогами.

!
Образ: сортировщик на почте

Представьте человека с двумя корзинами. Мимо едут конверты, он смотрит на каждый и кладёт либо в левую (true), либо в правую (false). Ни один конверт не выбрасывается и не вскрывается. К каждой корзине подходит свой курьер: к левой Telegram, к правой Google Sheets. Дальше в уроке мы будем возвращаться к этим корзинам.

Про две корзины

Посмотрите на схему под этим блоком. Нода If стоит посередине, и у неё две стрелки вправо. Верхняя подписана true, нижняя false. Представьте сортировщика на почте с двумя корзинами. Мимо едут конверты, он смотрит на каждый и кладёт в левую или в правую. Ни один конверт не выбрасывается. Верхняя стрелка ведёт в Telegram, туда уходят крупные заявки. Нижняя ведёт в Google Sheets, туда всё остальное. Запомните этот образ, мы будем к нему возвращаться.

ЗадачаПримерУсловие в If
Отделить важноеКрупные заявки в Telegram, остальные в таблицу{{ $json.amount }} · Number: is greater than · 1000
Отличить источникЗаявки с сайта обрабатывать сразу, из Instagram собирать в список{{ $json.source }} · String: is equal to · site
Поймать пустоеЕсли клиент не указал почту, отправить менеджеру напоминание позвонить{{ $json.email }} · String: is empty

Что внутри панели If

  • Conditions — список условий. У каждого три части: значение слева (обычно выражение, например {{ $json.amount }}), оператор и значение справа (число, текст или тоже выражение). Это основная настройка, с ней работаем всегда.
  • Оператор — выпадающий список, сгруппированный по типу данных: Number (is greater than, is less than, is equal to…), String (is equal to, contains, starts with, is empty…), Boolean (is true, is false), Date & Time (is after, is before), Array (contains, is empty). Выбирайте группу по типу того, что слева.
  • + Add condition и переключатель AND / OR между условиями. AND («и»): должны выполниться все. OR («или»): достаточно одного. Понадобится во втором тренажёре.
  • Convert types where required — переключатель внизу. Включён: n8n сам превращает текст «1200» в число 1200 перед сравнением. Выключен: сравнение текста с числом даёт ошибку. Держите включённым, пока не поймёте, зачем выключать.
  • Ignore Case — для текстовых операторов: «Site» и «site» считать одинаковыми. Пригодится, когда данные приходят от людей.
  • Options → Always Output Data — выдавать пустой элемент, даже если в ветку ничего не попало, чтобы следующая нода всё равно запустилась. Для первых workflow не нужно.
Прогноз. Условие «amount больше 1000». Пришли Анна (1200), Глеб (1000) и Дина (90). Кто окажется в корзине true?

Только Анна. Глеб с ровно 1000 уходит в false: «больше» — это строго больше, граница не входит. Если нужно включить 1000, берут оператор is greater than or equal to. Дина в false. Если вы ответили «Анна и Глеб», вы не одиноки: это самая частая ошибка с границами.

Что получается на выходе

На входе пять заявок. Смотрите, как одни и те же данные расходятся при разных условиях:

Вход (5 элементов)УсловиеВыход trueВыход false
Анна 1200 · Борис 350 · Вера 4800 · Глеб 1000 · Дина 90amount больше 1000Анна, Вера (2)Борис, Глеб, Дина (3)
те же пятьamount больше или равно 1000Анна, Вера, Глеб (3)Борис, Дина (2)
те же пятьsource равно siteАнна, Вера, Глеб (3)Борис, Дина (2)
те же пятьamount больше 1000 AND source равно siteАнна, Вера (2)Борис, Глеб, Дина (3)

В каждой строке true плюс false даёт пять. Сортировщик не теряет конверты.

Где искать пропавшую заявку

Самая частая жалоба на If звучит так: заявка пропала. Она была, и её нет. Откройте ноду If и посмотрите на правую панель, OUTPUT. Там две вкладки, true и false. Нажмите на false. Скорее всего, ваша заявка лежит здесь. Она не прошла условие, а к этому выходу ничего не подключено, поэтому она просто осталась в корзине. Ошибки нет, потому что с точки зрения n8n всё сработало правильно. Проверяйте вкладку false первой.

!
Ловушка: пустая корзина не ошибка, а тишина

Если к выходу false ничего не подключено, элементы из этой корзины просто остаются лежать. Workflow не упадёт и не предупредит. Для менеджера это выглядит как «заявка пропала»: она была, прошла If, и дальше с ней ничего не случилось. Поэтому, когда «что-то не доходит», первым делом откройте If и посмотрите вкладку false: скорее всего, нужный элемент лежит там.

Типы: когда число приходит как текст

Из форм и вебхуков сумма часто приходит в кавычках: "1200". Для n8n это текст (помните урок 4: кавычки — String). Что будет при разных операторах и положении переключателя Convert types:

Что слеваОператорConvert typesРезультат
1200 (число)Number: is greater than 1000любоеtrue, всё честно
"1200" (текст)Number: is greater than 1000включёнtrue: n8n сам перевёл текст в число
"1200" (текст)Number: is greater than 1000выключеношибка Wrong type: '1200' is a string but was expecting a number
"1200" (текст)String: is equal to 1200любоеtrue, но это сравнение букв, а не чисел
!
Типичная ошибка

Условие String → contains ищет подстроку: «1200» содержит «12». Для порога суммы выберите Number → is greater than. Если форма присылает число в кавычках, включите Convert types where required. Тогда «90» станет числом 90 и не пройдёт порог 1000.

Слева в условии почти всегда стоит выражение вида {{ $json.amount }}. Что такое выражения, вы разбирали в уроке 5. Здесь просто повторяйте готовые.

Проверьте себя
Условие «amount больше 1000», Convert types включён. Пришло 10 элементов, у 4 сумма больше 1000, ещё у 2 ровно 1000. Сколько элементов в ветке false?
  • 4: столько же, сколько и в true
  • 6: все, у кого не больше 1000
  • 2: только те, у кого ровно 1000
  • 0: не прошедшие удаляются

Практика: три ступени

ТренажёрСтупень 1, посмотреть. Условие уже настроено: сумма больше 1000. Просто нажмите Execute step и откройте вкладки true и false в OUTPUT. Найдите Глеба.
ТренажёрСтупень 2, вместе. Слева уже стоит {{ $json.amount }}. Выберите оператор и впишите число так, чтобы в true попали заявки больше 1000. Нажмите Execute step.
ТренажёрСтупень 3, сам. Условия пустые. Нужно, чтобы в true попали только крупные заявки с сайта: сумма больше 1000 и source равен site. Это два условия, соединённые так, чтобы выполнялись оба.
Как сломать и починить

В тренажёре ниже посмотрите на левую панель, INPUT. Суммы выглядят как числа, но это текст: они пришли из вебхука в кавычках. Внизу средней панели найдите переключатель Convert types where required. Выключите его и нажмите оранжевую кнопку Execute step. Над выходом появится красная плашка: Wrong type, строка вместо числа. Это и есть ошибка, которую вы будете встречать в реальных проектах. Теперь включите переключатель обратно и запустите ещё раз. Анна и Вера пройдут в true.

ТренажёрСломайте. Здесь суммы пришли из вебхука как текст: "1200". Условие настроено верно. Выключите Convert types where required и нажмите Execute step. Посмотрите на ошибку, потом включите обратно и убедитесь, что всё работает.

Что вы теперь умеете

  • Разделять поток на два по условию.
  • Соединять несколько условий через AND и OR.
  • Чинить ошибку Wrong type переключателем Convert types.

Подумайте о своём: какое письмо, заявка или событие у вас на работе делится на «срочно» и «потом»? По какому полю вы бы это поняли? Это и есть ваше первое условие для If.

Больше двух веток: нода Switch

If делит поток на две части. Если вариантов больше (источник заявки: сайт, Instagram, Telegram, звонок), используют Switch. У него столько выходов, сколько правил вы добавите, плюс необязательный выход Fallback для всего, что не подошло ни под одно правило.

Filter: когда вторая ветка не нужна

Если вам нужно только отбросить неподходящие элементы и ветка false никогда не пригодится, берите ноду Filter. Условия настраиваются так же, как в If, но выход один: прошли только подходящие. Холст получается чище.

Соединить ветки обратно: Merge

Иногда после разных веток нужно продолжить общую цепочку: крупные заявки получили пометку «VIP», мелкие — «обычная», а дальше все идут в одну таблицу. Для этого обе ветки подключают к ноде Merge, и она снова собирает элементы в один поток.

В Merge есть режим Append (просто сложить элементы из обеих веток), Combine (объединить по общему полю, например по email) и другие.

Итог урока

Главная мысль: If проверяет каждый элемент и отправляет его в ветку true или false. Элементы не теряются, а расходятся. Условие: что проверяем, оператор, с чем сравниваем.

  • If не теряет элементы: true плюс false всегда равно входу. Если «заявка пропала», смотрите вкладку false.
  • Операторы разбиты по типам: Number, String, Boolean, Date. Группа по типу того, что слева.
  • Число в кавычках — текст: включайте Convert types where required.
  • Несколько условий соединяются через AND или OR.
  • Switch — для трёх и более веток, Filter — когда нужна только одна, Merge собирает ветки обратно.
Проверка знаний
1. Сколько выходов у ноды If?
  • Один: прошедшие условие
  • Два: true и false
  • Столько, сколько условий
  • Столько, сколько элементов
2. Какой оператор выбрать, чтобы проверить «сумма больше 1000»?
  • String: contains
  • Number: is greater than
  • Number: is less than
  • Number: is greater than or equal to
3. Условие: amount > 1000. Куда попадёт элемент с amount = 1000?
  • В ветку true
  • В ветку false
  • В обе ветки сразу
  • Никуда: будет ошибка
4. Нужно пропустить заявки, где сумма больше 1000 И источник site. Как соединить два условия?
  • Через OR
  • Через AND
  • Двумя нодами If подряд
  • Через ноду Merge
5. Нужно разделить заявки по четырём источникам на четыре ветки. Какая нода подойдёт?
  • If
  • Filter
  • Switch
  • Merge
6. В If пришла сумма как текст "1200", и нода упала с ошибкой Wrong type. Что сделать?
  • Включить Convert types where required
  • Поменять оператор на String: contains
  • Заменить If на Filter
  • Добавить второе условие через OR
7. Повторение. Перед If стоит Edit Fields, и в нём поле sum задано с типом String. If с оператором Number падает с Wrong type. Что проще всего исправить?
  • В Edit Fields поставить полю sum тип Number
  • В If поменять оператор на String: contains
  • Убрать Edit Fields из цепочки совсем
  • Поменять местами If и Edit Fields
