Данные: элементы и JSON

Что именно бегает по стрелкам между нодами и почему нода иногда делает своё действие несколько раз.

Основная идея урока

Между нодами ходит не «просто информация», а список элементов (items). Каждый элемент — это набор полей вида «имя: значение», записанный в формате JSON. Нода получает список и обычно обрабатывает каждый элемент по очереди.

Один элемент — одна карточка

Представьте заявку из формы на сайте: имя, почта, сумма. В n8n она превратится в такой элемент:

{
  "name": "Анна",
  "email": "anna@mail.ru",
  "amount": 1200
}

Это JSON (читается «джейсон») — простой текстовый формат. Фигурные скобки — карточка. Внутри пары «поле: значение», разделённые запятыми. Текст в кавычках, числа без. Больше знать про JSON для начала не нужно.

  • "name": "Анна" — поле name со строкой (текстом).
  • "amount": 1200 — поле amount с числом. Без кавычек, поэтому с ним можно считать.
  • Поле может содержать вложенную карточку: "customer": { "city": "Минск" }. Тогда до города добираются через точку: customer.city.
  • Поле может содержать список в квадратных скобках: "tags": ["vip", "new"].

Список элементов — таблица

Если заявок три, триггер выдаст три элемента. Удобнее всего думать о них как о строках таблицы: каждая строка — элемент, каждый столбец — поле. Одна и та же карточка в двух видах:

JSON: как текстTable: как строка таблицы
{ "name": "Анна",
  "email": "anna@mail.ru",
  "amount": 1200 }
nameemailamount
Аннаanna@mail.ru1200

n8n так их и показывает во вкладке Table панели OUTPUT: три заявки — три строки.

ТренажёрВ ноде Edit Fields добавьте поле status со значением new и нажмите Execute step. Переключите OUTPUT на Table, JSON и Schema и сравните.

Три вида одной и той же информации: Table — как таблица, удобно глазами. JSON — как текст с фигурными скобками, видно вложенность. Schema — только имена полей и их типы, удобно, когда полей много. Переключайте, какой удобнее.

Прогноз. В ноду Telegram «отправить сообщение» пришло 3 элемента: Анна, Борис, Вера. Сколько сообщений получит менеджер?

Три. Нода выполняет своё действие для каждого элемента отдельно: три элемента, три сообщения, по одному на заявку. На холсте это по-прежнему один запуск: одна галочка и подпись «3 items». Если вы ответили «одно сообщение со списком», так думают почти все. Чтобы получилось одно, элементы сначала нужно собрать в один специальной нодой Aggregate, о ней в конце урока.

!
Правило «по элементу»

Пришло 3 элемента — нода сделает своё действие 3 раза и выдаст 3 результата. Пришёл 1 — один раз. Нода Telegram с тремя элементами на входе отправит три сообщения. На холсте это по-прежнему один запуск: одна галочка и подпись «3 items». Это главное, что надо понять про данные в n8n.

Проверьте себя
Нода Google Sheets «добавить строку». На входе 4 элемента. Что появится в таблице после выполнения?
  • Одна строка с четырьмя заявками
  • Четыре строки, по одной на элемент
  • Ничего: нужно четыре ноды Sheets
  • Четыре строки, но только после Save

Нода Edit Fields: ваш швейцарский нож

Edit Fields (раньше называлась Set, в панели написано «Edit Fields (Set)») — самая частая нода для работы с данными. Она ничего не отправляет и никуда не ходит: берёт элементы со входа, меняет в них поля и отдаёт дальше. Три типичные задачи:

ЗадачаПримерЧто настроить
Добавить полеК каждой заявке дописать status: new или дату обработкиНовая строка в Fields to Set: имя status, значение new
Переименовать полеСервис отдал first_name, а Google Sheets ждёт столбец ИмяПоле Имя со значением {{ $json.first_name }}, а старое убрать
Убрать лишнееВ таблицу не должен попасть email и внутренний idВыключить Include Other Input Fields и перечислить только нужные поля

Что внутри панели ноды

Откройте ноду двойным щелчком. Слева INPUT (что пришло), справа OUTPUT (что получилось), посередине настройки. Их немного:

  • Mode — как задавать поля. Manual Mapping: построчно, по одному полю, через форму. Это основной режим, и в курсе используем только его. JSON: вписать сразу всю карточку текстом в фигурных скобках. Удобно, когда полей десять и их проще скопировать из документации.
  • Fields to Set — список полей, которые нода запишет в каждый элемент. Кнопка + Add Field добавляет строку. У каждой строки три части: name (имя поля), type (тип: String, Number, Boolean, Array, Object) и value (значение).
  • Include Other Input Fields — оставлять ли поля, которые пришли на вход. Включён: входные поля остаются, ваши добавляются к ним. Выключен: на выходе только то, что перечислено в Fields to Set.
  • Options — редкие настройки. Например, Support Dot Notation: имя customer.city создаст вложенную карточку customer с полем city, а не поле с точкой в названии. Для первых workflow сюда заглядывать не нужно.

Как нода меняет элемент

Входной элемент — заявка с тремя полями. В Fields to Set одна строка: status = new. Смотрите, что получается при двух положениях переключателя:

ВходInclude Other Input Fields включёнInclude Other Input Fields выключен
{ "name": "Анна",
  "email": "anna@mail.ru",
  "amount": 1200 }
{ "name": "Анна",
  "email": "anna@mail.ru",
  "amount": 1200,
  "status": "new" }
{ "status": "new" }

Если в Fields to Set указать имя, которое уже есть на входе, старое значение перезапишется. Так, строка amount = 0 обнулит сумму у всех элементов. Это удобно для исправлений, но легко сделать случайно: проверяйте OUTPUT после Execute step.

ТренажёрСломайте. Поле amount уже есть у каждой заявки. Нажмите «+ Add Field», впишите имя amount и значение 0, выполните Execute step и посмотрите на суммы в OUTPUT. Потом удалите строку крестиком и выполните ещё раз.
!
Нода работает с каждым элементом отдельно

Пришло три заявки — нода трижды выполнит одни и те же строки Fields to Set, по разу на заявку. Значение new получат все три. А выражение {{ $json.name }} для каждой подставит её имя: Анна, Борис, Вера. Поэтому в OUTPUT всегда столько же элементов, сколько в INPUT.

Тип поля: почему он важен

Выпадающий список рядом с именем задаёт, чем будет значение. Ошибка в типе — самая частая причина, по которой «не считается» или «не сравнивается» в ноде If.

ТипЧто этоПример значенияВ JSON будет
StringТекстnew, Анна, 1200"1200" (в кавычках: с этим нельзя считать)
NumberЧисло1200, 3.51200 (без кавычек: можно складывать и сравнивать)
BooleanДа или нетtrue, falsetrue
ArrayСписок["vip", "new"]["vip","new"]
ObjectВложенная карточка{ "city": "Минск" }{"city":"Минск"}
!
Типичная ошибка

Поле sum с типом String и значением 1200 в ноде If не пройдёт проверку «Number: is greater than 1000»: n8n увидит текст, а не число. Либо ставьте тип Number, либо в If выбирайте условие для строк. Правило простое: всё, с чем будут считать или сравнивать как числа, делайте Number.

Чтобы положить в новое поле значение из входных данных, вместо обычного текста пишут выражение в двойных фигурных скобках: {{ $json.name }} означает «возьми поле name текущего элемента». Выражениям посвящён весь следующий урок, а здесь просто повторите два готовых.

Проверьте себя
В Fields to Set одна строка: status = new. Include Other Input Fields выключен. На входе заявка с полями name, email, amount. Что будет на выходе?
  • Четыре поля: name, email, amount и status
  • Одно поле status со значением new
  • Три поля name, email, amount без изменений
  • Ошибка: нельзя выключать переключатель при одном поле
ТренажёрСделайте так, чтобы на выходе остались только два поля: client с именем и sum с суммой. Поле email должно исчезнуть.

Что вы теперь умеете

  • Читать элемент как карточку с полями, а список элементов как таблицу.
  • Добавлять, переименовывать и убирать поля в Edit Fields.
  • Ставить тип Number всему, с чем будут считать или сравнивать.

Подумайте о своём: какие поля у заявки или письма из вашей рутины (урок 1)? Назовите три. Что из них число, а что текст? Эти поля вы будете подставлять в сообщения в уроке 5 и проверять в уроке 6.

Режим JSON: все поля одним текстом

Переключите Mode на JSON, и вместо строк появится одно большое поле. В него вписывают готовую карточку. Это те же поля, что и в Manual Mapping, просто записаны текстом:

{
  "status": "new",
  "client": "{{ $json.name }}",
  "sum": {{ $json.amount }}
}

Обратите внимание на кавычки: выражение для текста берут в кавычки, для числа — нет. Режим удобен, когда полей много или структуру дали в документации сервиса. Для первых workflow хватает Manual Mapping.

Ноды, которые меняют количество элементов

Иногда правило «по элементу» нужно нарушить. Для этого есть специальные ноды.

НодаЧто делаетПример
AggregateМного элементов → одинСобрать 20 заявок в один список для одного письма-отчёта
Split OutОдин элемент со списком внутри → многоСервис вернул одну карточку с полем orders из 10 заказов, нужно 10 элементов
FilterОставить только подходящиеПропустить дальше только заявки дороже 1000
LimitОставить первые NВзять только 5 последних новостей
Remove DuplicatesУбрать повторыОдин клиент прислал две одинаковые заявки
Настройка Execute Once

Во вкладке Settings любой ноды есть переключатель Execute Once. Если его включить, нода отработает один раз для первого элемента, а остальные проигнорирует. Полезно, когда нужно одно уведомление «пришли новые заявки», а не по сообщению на каждую.

Бинарные данные: файлы и картинки

Кроме JSON у элемента может быть часть binary — файл: PDF, фото, таблица Excel. В панели OUTPUT для таких элементов появляется вкладка Binary. Файлы передаются по стрелкам так же, как и JSON, и, например, нода Telegram может отправить фото из binary. Для первых workflow это редко нужно.

Итог урока

Главная мысль: По стрелкам ходит список элементов. Каждый элемент — JSON-карточка с полями. Нода обрабатывает каждый элемент по очереди: сколько пришло, столько раз и сделает своё действие.

  • Table, JSON, Schema — три вида одних и тех же данных.
  • Поле с текстом в кавычках, число без, вложенность через точку.
  • Edit Fields добавляет, переименовывает и убирает поля; тип поля (String/Number) решает, можно ли с ним считать.
  • Чтобы из многих элементов сделать один, есть Aggregate; наоборот — Split Out.
Проверка знаний
1. Gmail Trigger нашёл три новых письма. Что увидит следующая нода в панели INPUT?
  • Три элемента, по одному на письмо
  • Один элемент со списком из трёх писем
  • Три запуска workflow подряд
  • Одно письмо, остальные два ждут очереди
2. В JSON записано "amount": 1200. Что можно сказать о поле amount?
  • Это текст, считать с ним нельзя
  • Это число, с ним можно считать
  • Это список из одного значения
  • Это ошибка: нужны кавычки
3. В ноду пришло 4 элемента. Сколько раз она сделает своё действие по умолчанию?
  • Один раз, для первого элемента
  • Два раза: по половине элементов
  • Четыре раза, по одному на элемент
  • Ни разу, пока не включить Execute Once
4. Нужно, чтобы на выходе Edit Fields остались только заданные вами поля. Что сделать?
  • Выключить Include Other Input Fields
  • Включить Execute Once во вкладке Settings
  • Переключить OUTPUT на вкладку Schema
  • Удалить лишние поля во вкладке INPUT
5. Какая нода соберёт 20 элементов в один, чтобы отправить одно письмо-отчёт?
  • Split Out
  • Filter
  • Aggregate
  • Limit
6. В какой вкладке панели OUTPUT видны только имена полей и их типы?
  • Table
  • JSON
  • Schema
  • Binary
7. Повторение. После запуска у Edit Fields зелёная галочка и «3 items», а следующая нода Telegram серая, без галочки. Что это значит?
  • Telegram ещё не выполнялась: запуск до неё не дошёл
  • Telegram отправила три сообщения, но галочку не показала
  • Edit Fields упала на третьем элементе
  • Workflow не сохранён, поэтому Telegram серая
8. Повторение. В панели нод вы ищете ноду, которая добавит к заявке поле status. Что печатать в поиске?
  • edit или set
  • status

  • add field
