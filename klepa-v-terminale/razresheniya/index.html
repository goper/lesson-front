Разрешения: что Клёпа делает сама, а о чём спрашивает

Перед командой в терминале Клёпа показывает окно «Требуется разрешение» с тремя ответами. Разбираем, что значит каждый, и почему средний ответ опаснее, чем кажется.

~12 минут 1 прогноз 3 вопроса с разбором Практика в своём терминале

После урока вы сможете

  • читать окно разрешения и выбирать один из трёх ответов осознанно;
  • сказать заранее, про какое действие Клёпа спросит, а про какое нет;
  • найти и убрать правило, которое вы когда-то разрешили навсегда.
1 Проблема

Три кнопки, а вы торопитесь

Клёпа закончила правку в проекте магазина и хочет выполнить git push origin main. На экране окно с тремя ответами. Вы торопитесь на созвон и выбираете средний — «Разрешать всегда»: пусть больше не отвлекает.

Через неделю вы работаете в другом проекте, сайте клиента. Просите Клёпу «закоммить правки». Она спрашивает про коммит, вы соглашаетесь — и следом ветка main уходит на сервер уже без вопроса. А в этом проекте в main отправляют только после проверки.

Клёпа ничего не нарушила: неделю назад вы сами разрешили это навсегда. Чтобы так не попадать, надо понимать, что стоит за каждой из трёх кнопок.

2 Что это

Разрешение — вопрос «можно?» перед рискованным шагом

Что делает. Перед действием, которое может что-то сломать или вынести наружу, Клёпа останавливается и показывает окно «Требуется разрешение». Пока вы не ответите, действие не выполняется.

Чего не делает. Клёпа не спрашивает про правку файлов в папке проекта: их она меняет сама. И окно не оценивает, хороша ли команда: оно только показывает её вам. Решение ваше.

Представьте

Мастер в вашей комнате своим инструментом работает молча. Но перед тем как перекрыть воду в стояке, зайти в соседнюю комнату или открыть сейф, он звонит вам: «можно?». Ответить можно «да, сейчас», «нет» или «да, и больше не спрашивай». Третий ответ — это связка ключей, которую вы отдали насовсем.

Работа своим инструментом= правка файлов проекта
Перекрыть воду= команда в терминале
Соседняя комната= файл вне папки проекта
Сейф= файл .env с паролями

Три частые задачи

ЗадачаПримерЧто сделать
Разовая команда, в которой вы увереныnode --test после правки«Разрешить один раз»
Безопасная команда, которая нужна сто раз в деньnpm test в рабочем проекте«Разрешать всегда», прочитать шаблон, «Подтвердить»
Опасная или непонятная командаgit push origin main, rm -rf build«Отказать» и следующим сообщением написать, как поступить иначе

Что внутри

Идёт без вопроса в режиме «Код»:

  • чтение и правка файлов в папке проекта;
  • поиск по проекту и чтение страниц в интернете;
  • команды, которые только читают: ls, cat, head, tail, grep, rg, wc, diff, sort, jq, pwd, which;
  • простые действия с файлами: mkdir, touch, cp, mv, распаковка архивов.

Спрашивает:

  • Любая другая команда в терминале — npm, node, git, rm, docker, curl. В курсе: главный случай.
  • Чтение файлов .env и .env.что-то. Файл .env.example читается без вопроса. В курсе: да.
  • Файл вне папки проекта — чтение и правка. В курсе: да.
  • Правка AGENTS.md и файлов настроек Клёпы — спрашивает каждый раз, ответа «Разрешать всегда» здесь нет. Встретится в уроке 7.

Окно разрешения:

  • «Разрешить один раз» — выполнить сейчас. В следующий раз спросит снова.
  • «Разрешать всегда» — открывает второе окно со строкой «Эти шаблоны будут разрешены постоянно» и списком, например git push *. Дальше «Подтвердить» или «Отмена».
  • «Отказать» — действие не выполнится. Клёпа узнает об отказе и остановится или найдёт другой путь.
3 Как работает

Один вопрос, три ответа, три разных будущих

Сначала прогноз

Клёпа в режиме «Код» чинит корзину. Какое из этих действий она сделает без вопроса?

Файлы в папке проекта Клёпа правит сама. Вопрос появляется перед командой в терминале и перед чтением .env.

  • «Запустит тест». Так отвечают чаще всего: тест кажется безобидным, а правка кода — серьёзной. У Клёпы наоборот. Правку видно в git diff и её можно вернуть, а команда в терминале может сделать что угодно: для программы node --test и rm -rf — одинаково «какая-то команда».
  • «Прочитает .env». Чтение обычно безопасно, поэтому так подумать легко. Но в .env лежат пароли и ключи, и прочитанное уходит в модель. Это сейф: туда мастер без звонка не заглядывает.

Было → стало

Клёпа просит выполнить git push origin main. Вот что будет после каждого ответа.

Ваш ответЧто происходит сейчасЧто будет в следующий раз
«Разрешить один раз»Ветка отправленаКлёпа спросит снова
«Разрешать всегда» → «Подтвердить»Ветка отправлена. В общий файл настроек записано правило: 
"permission": {
  "bash": {
    "git push *": "allow"
  }
}
Не спросит. Ни в этом проекте, ни в любом другом
«Отказать»Ничего не отправлено. Клёпа сообщает, что команда отклоненаКлёпа спросит снова
Ловушка: «всегда» — это навсегда и везде«Разрешать всегда» действует не до конца диалога и не в одном проекте. Правило записывается в общий файл настроек Клёпы и работает во всех папках, пока вы сами его не удалите. Вы отдали мастеру ключи от стояка — и он пользуется ими в каждой квартире, куда вы его позовёте. Перед «Подтвердить» прочитайте шаблон: git push * разрешает любую отправку, в любую ветку.

Три значения правила

То же самое можно записать руками: в файле klepa.json в папке проекта или в общем файле настроек. На Linux и macOS он лежит в ~/.config/klepa-cli/klepa.jsonc.

ВариантЧто этоПримерКак выглядит в результате
"allow"Выполнять без вопроса"npm test *": "allow"Тесты запускаются сразу, окна нет
"ask"Спрашивать каждый раз"*": "ask"Окно «Требуется разрешение»
"deny"Запретить совсем"git push *": "deny"Команда не выполняется, окна нет
Типичная ошибкаНажать «Разрешать всегда» на команде, которая что-то отправляет, удаляет или устанавливает: git push, rm, npm install, скрипт выкладки. Правило простое. «Всегда» — только для команд, которые ничего не меняют за пределами проекта: тесты, линтер, сборка. Всё остальное — «один раз», сколько бы раз ни пришлось нажать.

В следующем уроке появится знак !: с ним команду в терминале выполняете вы сами, прямо из окна Клёпы. Про такие команды окно разрешения не спрашивает. Пока просто запомните разницу: спрашивают про команды Клёпы, а не про ваши.

4 Проверка

Вопрос по сценарию и два на повторение

Проверьте себя

В проекте shop Дима ответил «Разрешать всегда» на шаблон npm test * и нажал «Подтвердить». Назавтра он открыл Клёпу в проекте blog и попросил прогнать тесты. Что будет?

Правило записано в общий файл настроек и действует во всех проектах. Для тестов это обычно удобно. Для git push — уже нет.

  • «Только для shop». Самая частая догадка: кажется естественным, что ключи выданы для одной комнаты. На деле связка общая.
  • «До конца диалога». Так работает «Разрешить один раз», и то лишь для одной команды. «Всегда» переживает и диалог, и перезапуск.
  • «Клёпа откажется». Отказ без окна бывает только при правиле "deny". Здесь его никто не писал.

Повторение. Включён режим «Вопросы». По ходу ответа Клёпе понадобилось выполнить npm install. Что вы увидите?

В «Вопросах» и «Плане» работают только читающие команды — это урок 2. Всё, что может менять проект, запрещено заранее, и окна не будет.

  • «Окно с тремя ответами». После этого урока так ответить легко: команда в терминале — значит окно. Но окно появляется там, где действие вообще возможно, то есть в «Коде» и «Отладке».
  • «Выполнится: это не правка». Установка пакетов меняет папку node_modules и файлы проекта. Режим смотрит на команду, а не на намерение.
  • «Сама перейдёт в „Код“». Режим переключаете только вы, клавишей Tab.

Повторение. Вы работаете в проекте shop. Клёпа просит разрешение прочитать ~/projects/blog/config.js. Почему появился вопрос, ведь чтение файлов идёт без него?

Проект для Клёпы — папка запуска, как в уроке 1. Всё, что за её пределами, — соседняя комната: туда только после вопроса.

  • «Приравнен к .env». Слово config настораживает, но особое правило есть только для файлов .env. Такой же config.js внутри shop прочитался бы молча.
  • «На любое чтение». Внутри проекта чтение свободное в любом режиме.
  • «Модель не уверена». Окно разрешения не про сомнения модели. Его показывает сама программа по своим правилам.
5 Практика

Три ответа на трёх ступенях

Работаем в папке cart. Верните ошибку: git restore cart.mjs.

Ступень 1 · Всё готово, повторите
  1. Откройте Клёпу в режиме «Код» и отправьте: 
    Исправь расчёт скидки в cart.mjs и проверь командой node --test.
  2. Дождитесь окна «Требуется разрешение». Прочитайте, какая команда в нём написана.
  3. Выберите «Разрешить один раз».
  4. Попросите ещё раз: «Запусти node --test снова».
Что должно получиться — сверьтесь

Файл cart.mjs Клёпа поправила без вопроса. Окно появилось только перед node --test. На второй запуск окно появилось снова: «один раз» значит один раз.

Ступень 2 · Половина готова, доделайте
  1. Выйдите из Клёпы и создайте в папке корзины файл с «секретом»: 
    echo "PAYMENT_KEY=test-123" > .env
  2. Откройте Клёпу и попросите: 
    Какие переменные заданы в файле .env?
  3. В окне выберите ответ, после которого Клёпа не узнает содержимое файла. Посмотрите, что она напишет.
Подсказка — если застряли

Нужен ответ «Отказать». Клёпа сообщит, что доступ к файлу отклонён, и значения test-123 в ответе не будет. После опыта удалите файл: rm .env.

Если окно не появилось, значит Клёпа прочитала файл командой cat: читающие команды идут без вопроса. Поэтому окно про .env — страховка от случайного чтения, а не замок. Настоящие ключи надёжнее держать вне папки проекта.

Ступень 3 · Сами, в своём проекте

В своём проекте выберите одну команду, которую не страшно разрешить навсегда: запуск тестов или линтера. Добейтесь, чтобы Клёпа выполняла её без окна. Потом найдите это правило в общем файле настроек.

Готово, когда команда выполняется без вопроса, а вы можете показать строку с ней в блоке permission. Чтобы отозвать разрешение, удалите эту строку.

Сломайте · Отказ на проверку
  1. Верните ошибку: git restore cart.mjs. Откройте Клёпу.
  2. Отправьте ту же задачу: «Исправь расчёт скидки в cart.mjs и проверь командой node --test».
  3. В окне выберите «Отказать».

Правка сделана, а проверки нет: Клёпа честно пишет, что тест запустить не удалось. Отказ не ломает работу, но и результат остаётся непроверенным — проверьте сами.

Необязательное: правила в файле проекта — klepa.json

Правила для одного проекта удобно хранить рядом с кодом. Создайте в корне проекта файл klepa.json:

{
  "permission": {
    "bash": {
      "*": "ask",
      "node --test *": "allow",
      "git push *": "deny"
    }
  }
}

На что смотреть: тесты пойдут без окна, отправка на сервер не выполнится вообще, про остальное Клёпа спросит. Действует правило, записанное ниже: общее "*" стоит первым, уточнения — после него.

6 Итог

Что вы теперь умеете

  • Читать окно разрешения: какая команда и какой шаблон.
  • Выбирать между «один раз», «всегда» и «отказать» по последствиям.
  • Отзывать разрешение, выданное навсегда, в файле настроек.

Примерьте к своей задаче

Ваша задача из урока 1:

Проверки нет: это заметка для вас. Ответ появится в вашей схеме на карте курса.

Главное правило урокаПеред «Разрешать всегда» читайте шаблон: правило останется навсегда и во всех проектах. «Всегда» — только для тестов, линтера и сборки.

Отметьте, что усвоили

  • Знаю, что файлы проекта Клёпа правит без вопроса, а про команды в терминале спрашивает.
  • Знаю, что про .env и файлы вне проекта она тоже спрашивает.
  • Понимаю разницу между «Разрешить один раз», «Разрешать всегда» и «Отказать».
  • Читаю шаблон во втором окне перед «Подтвердить».
  • Знаю, где лежит общий файл настроек и как убрать из него правило.
